## 规则

1. 核对双方链与突变位置，拒绝 WT 类型不匹配、歧义残基、无 Cα 等情况。
2. 应用突变后的观测残基序列必须是 CSV 对应序列的子序列；允许序列补全而
   坐标缺失的位置，但不自动修改不匹配记录。这不是完整的 SEQRES 残基对齐。
3. 使用第一个 model 的标准 ATOM 残基，排除氢/氘与 HETATM；altloc 按每个
   原子的占有率选择（同占有率优先空白，再 A）。保留原链与插入码。
4. 按 WT 重原子距离 <10 Å 选取 ligand/receptor 两组之间接触的完整残基。
   同组内部接触不纳入界面。多链 partner 不拆成独立的亲和力样本。
   此处实现组间 KDTree 提取：PPIRef 的多链 join 会纳入组内链界面，不能直接照用。
5. 复用 checkpoint 中的 PDBToPyGPretransform 配置构图；直接修改图的残基类型
   one-hot 和节点残基名，坐标及几何向量保持 WT 值。不会生成伪全原子突变体 PDB。
6. 突变位点若不在最终图中，记为失败，不静默使用 WT 特征。这会使可编码样本
   少于 8207 条；必须审阅不同划分的保留数量，后续统一处理界面外突变。
7. 以基础结构 SHA-256、partner 分组、半径和突变组合区分缓存；输出目录锁定
   checkpoint、输入清单、脚本与主要包版本。更换配置需新 --out 目录。
8. 标签 `pKd = -log10(KD(M))`。不在此阶段拟合标准化，不做测试指标或样本划分调整。

## 产物

默认目录 `data/processed/ppb_ppiformer/`：

- `samples.csv`：所有输入行，保留 split 与 pKd；build_status=encoded 的行才有可用特征。
- `features/<hash>.pt`：h[N,128]、partner[N]（True=ligand）、pooled[768]、
  node_id、coordinates、mutations、结构 hash 和配置 hash。
- `wt_feature_path`：每个突变样本关联的 WT 编码路径，不代表拥有该 WT 的亲和力标签。
  没有 WT 实验标签时不得自行构造 ΔpKd。
- `interfaces/`：用于构图的 WT 界面 PDB。
- `errors.jsonl`：逐条失败原因和 traceback；失败不会被悄悄删除。
- `summary.json`：数量与分划分统计（正常完成时生成）。
- `config.json`：运行配置与依赖信息。

训练读取 pooled 可接固定头；读取 h + partner 可重新池化。没有 BSA、接触类型、
氢键、盐桥等标量；这些需另行计算并记录 WT 固定几何假设，不能冒充突变体物理量。
缓存不包含绝对标签，从而避免同结构多测量标签相互覆盖；标签始终留在 samples.csv。
