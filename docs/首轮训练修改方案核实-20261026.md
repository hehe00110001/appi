# 首轮训练修改方案核实（2026-10-26）

核实对象：附件《修改方案-首轮训练问题修复.md》。本次按“核实意见”处理，附件中的执行命令、修改优先级和验收要求均作为待审建议，不作为修改训练流水线的授权。

结论：来源失衡、当前联合训练退化、差分预测幅度较小确实存在；标定诊断、补充指标和逐项消融值得做。但附件混用了错误样本数、旧版代码和未经验证的因果解释，不能整份直接实施。最关键的错误是“约 200 条 pair、每条影响约 22 倍”和“2034 条序列失败可能主要由 WT/突变方向错误造成”。前者实际是 3556 条及约 1.257 倍；后者经全量检查，改用 WT 序列可通过的记录为 0。

**1. 标定：确有改善空间，但“主要是偏移/几乎没有预测力”的说法不准确**

以下是三 seed 的均值±样本标准差，绝对值单位为 pKd；不代表样本泛化置信区间。

| 模式 | 原始 test RMSE | 验证集拟合仿射标定后的 test RMSE | 仅验证集均值纠偏后的 test RMSE |
|---|---:|---:|---:|
| absolute | 1.64398 ± 0.01337 | 1.56537 ± 0.01441 | 1.63673 |
| joint | 1.93059 ± 0.02861 | 1.62026 ± 0.00447 | 1.92345 |

测试标签总体标准差为 1.68726。absolute 比“已知测试集自身均值”的 oracle 常数误差低约 2.57%，附件的近似算术成立；但测试均值需要测试标签，不能作为可部署基线。训练均值基线 test RMSE 约 1.939，仍应同时报告。

`Pearson²` 不是当前模型的预测 `R² = 1 - SSE/SST`。absolute 三个 seed 的实际 R² 分别为 0.04450、0.06813、0.03919，平均约 0.0506，而不是 0.15。`σ_y * sqrt(1-r²)` 是在同一集合上允许任意最优仿射重标定时的诊断下限；它不是保证可在独立测试集实现的误差。

absolute 测试 bias 分别为 -0.06035、+0.23052、+0.15663，对应 bias²/MSE 为 0.134%、2.003%、0.897%。joint 对应为 0.524%、0.014%、1.892%。因此不能把当前误差主要归因于全局均值偏移。

absolute 验证集拟合斜率为 0.676/0.728/0.713，joint 为 0.359/0.354/0.370，均小于 1：本次有效的仿射校准进一步压缩预测幅度。预测标准差小于标签标准差，本身不证明应该把预测拉宽；平方损失下条件均值的方差本来就可能小于标签方差。标定后仍有约 1.57/1.62 的误差，不能推断“问题只在标定，不在表征”。

附件 A 对 absolute 和 pairs 分别拟合带截距的仿射映射，有额外的模型语义问题。共享评分 `S'=aS+b` 必须满足 `ΔS'=aΔS`，截距消失，不能另加一个差分截距。本次按 absolute 的同一组标定参数约束差分，test ΔpKd RMSE 为：

| 模式 | 原始差分 RMSE | 共享 absolute 标定后的差分 RMSE |
|---|---:|---:|
| absolute | 0.98408 | 0.99784 |
| joint | 0.93037 | 0.99136 |

可见绝对值标定变好不等于联合任务一起变好。独立拟合 pairs 得到的约 0.950/0.911 只能作为另一种诊断，不能冒充共享评分模型的结果。差分 val/test 仅 32/13 条，且一个 absolute seed 的验证差分拟合斜率为负，进一步说明不宜据此确定差分标定方案。

**2. pair 权重：样本数错误使附件的 λ 换算失效**

实际清单为 absolute/train=4470、pairs/train=3556。训练循环每个绝对 batch 抽取等大小差分 batch，两项都是以同一 target_scale 标准化后的均方误差：

`L = mean_abs(loss_i) + λ * mean_pair(loss_j)`。

按平均目标中每条记录的系数计算，λ=1 时两类记录的比值约为 `4470/3556=1.25703`，不是 22。该比值只描述目标系数，并不保证实际梯度影响相等，因为差分样本涉及两个评分、残差和导数也不同。

附件提出的 per_sample 乘数实际是 `3556/4470=0.795526`。原 per_task λ=0.05/0.1/0.3 分别对应 per_sample λ≈0.0629/0.1257/0.3771。新建议的 per_sample 0.25/0.5/1/2 则对应现有代码 λ≈0.1989/0.3978/0.7955/1.5911，是另一组搜索范围，并非必要的“22 倍纠偏”。

明确记录任务权重有价值，但当前 MSE 已归一化，不能称作在“未归一化的量”上扫描。既有低 λ 验证集对照仍有意义。若更换口径，应在报告里给出实际乘到 `L_diff` 上的系数。

**4. 复合物重复需要关注，但附件的键和 Kish 解释不对**

实际来源列为 `Source Data Set`，不在附件 A/B 的 `SOURCE_KEYS` 中，原样运行会漏掉所有 absolute 来源统计。absolute 的 `Complex ID` 含突变和实验信息：4470 条训练记录恰有 4470 个不同值。用它统计、重加权时，每条权重都是 1，无法实现基础复合物平衡。`PDB` 大写也不在其 ID 候选列表中；只用 PDB 本身仍会合并同结构里的不同链对。

使用“PDB + 双方链集合（双方交换不敏感）”后：

- absolute train：616 个基础复合物键、499 个 PDB，其中 SKEMPI 的 3995 条来自 236 个基础复合物键。
- pairs train：3556 条，184 个基础复合物键、183 个 PDB。
- 按该键，两种任务各自 train/val/test 的两两交集均为 0。
- 附件公式 `(Σn_i)²/Σn_i²` 对 absolute train 得 59.8535，pairs train 得 43.3376；不是“约 1000”。

这个公式在这里表示“按记录占比加权的复合物数量集中度”，不能无条件等同于统计有效样本量。只有在特殊的簇内完全相关、簇间独立等假设下，才有相应的有效样本解释。突变记录不是完全重复观测，不同 PDB 还可能同源，不能把这个数直接作为论文的独立样本量。

按特征文件路径检查：4470 条训练记录引用 4457 个不同文件；重复路径中没有标签冲突，组内标签方差为 0。这否定“当前已有大量同一特征文件对应冲突标签”的具体说法，但不排除不同文件中存在相近甚至相同的向量，也不排除同体系样本高度相关。

C2 还需要修正两点：

- 在均匀小批量抽样下，`sum(w*loss)/sum(batch_weights)` 是随机比值，不严格等于预期的全数据复合物等权目标；batch=1 时权重完全抵消。全局权重归一至均值 1 后采用 `(w*loss).mean()`，或明确使用复合物均匀抽样，目标更清晰。
- 按 `feature_path` 去重不等于按复合物等权。不同突变体仍对应不同文件，高频复合物仍会影响特征统计。是否同步改变特征/标签标准化应作为明确设计选择，不应宣称去重已经解决；更改 target_scale 还会改变优化尺度，应单独记录。

**5. max pooling：可试，但机制与验收标准说得过满**

当前池化同时包含 mean 和 sum，然后组合双方的和、绝对差及逐元素乘积。编码器有残基间信息传播，“只改一个输入 one-hot”不等于“只改一个输出残基 embedding”。对只有一个输出节点变化的简化情况，mean 的绝对变化才是 Δh/N；这不能直接给出标准化后整模型的预测变化。

sum 已保留未除 N 的信息，后续还有训练集标准化和 LayerNorm。max 在被改变的残基未成为维度最大值时，可能完全不变，不能保证更敏感。新增 max 后即使输出 std 变大，也可能只是放大错误或噪声；应同时报告 RMSE/MAE、bias、相关性、验证表现及合适的不确定性。

已有 `outputs/mutation_sensitivity/report.json` 在一例 SC16A 上记录：WT 重复编码差为 0，突变位点 embedding 的 L2 变化为 7.9207，最大绝对变化为 1.7867。因此至少该例中冻结编码器响应突变。它不能证明携带足够亲和力信息，也不能由 max 消融无效反推出“冻结特征不含突变信息”。

从缓存 `h` 重算池化无需重跑编码器，这点正确。但 D2/D3 不是完整迁移：

- 当前清单引用多个缓存目录，必须覆盖实际引用文件并为新实验改写清单中的 mut/WT 路径，否则训练仍读旧 768 维向量。
- 修改 pooled 后保留原 `config_sha256` 会使缓存 provenance 不完整，应记录来源哈希、池化配置/代码哈希与新版本。
- D1 的 `AffinityHead(pool_blocks=6)` 仍调用固定输出 9 个块的 `symmetric_pool`，直接 `forward(h, partner)` 会维度不匹配；应把池化模式本身参数化。
- 若组合 F 的 7 个标量，D3 的 `dim % 128 == 0` 检查及 `pool_blocks=dim//128` 不能用于总输入维度，需区分 embedding 与 scalar 宽度，并核对全部文件的标量名称顺序。

**6. 独立差分头和官方方法的说法需要更正**

局部残基差分头值得作为对照，但实验结果不保证是共享评分模型的“上界”。若不施加额外约束，它也不保证正反突变反对称或循环一致性。

附件称 PPIformer 也采用这类独立差分回归头，并不准确。PPIformer 主方法从突变位点的氨基酸概率 log-odds 得到差分；embedding 拼接/差分回归是它论文附录 D.2 的对照方法。官方代码 `predict_ddg` 也将二者标为 baselines。见 [PPIformer 原论文，正文 4.4 与附录 D.2](https://proceedings.iclr.cc/paper_files/paper/2024/file/5b4263be85820683d78675cc18d2efc7-Paper-Conference.pdf)。

**7. 新划分可以研究，但不是在已有完整同源隔离上补一个 source 约束**

当前默认规则明确没有剔除所有单链相似性命中；严格 30% identity/80% 覆盖筛查仅作为另一个版本，曾将绝对训练条数降至 709。零复合物键交集不证明同源隔离。

如果新增划分，需先定义泄漏单位、聚类阈值、连接规则及对自有 holdout 的排除，再整簇分配。含多个来源的簇应按完整来源计数向量评估，不能仅看 dominant source。大簇可能使每折来源比例偏差 <5% 不可行；需报告可行性与实际偏差。来源平衡、标签均值接近和任务泛化是不同目标，不应把测试标签均值相似作为调分结果的验收目标。

保留当前作者 split 子集作为一套协议；另设来源平衡/聚类隔离协议，结果分别报告。已有测试集已用于结果分析，后续配置选择仍应只基于验证集或新的开发协议。

**8. 界面标量值得做，但 F 中有明确数学和实现错误**

当前未显式加入 BSA/接触标量，正确；“完全没有界面规模信息”过强，因为 sum 池化可能编码部分规模信息。额外标量的增益需要对照。

固定 WT 几何不代表化学组成不变：例如 Lys→Ala 会改变带电/极性残基计数。若复制 WT 的这些标量给 mutant，它们只能称为 WT 背景描述符，不能称为突变体自身的组成。

即使某个几何标量 s 对 WT/mut 完全相同，当前非线性拼接模型中也不一定抵消：`S(z_mut,s)-S(z_wt,s)` 可以依赖 s。例如 `S(z,s)=z*s` 时，差分为 `s*(z_mut-z_wt)`。只有显式可加且不与 z 交互的分支 `g(z)+h(s)` 中，h(s) 才严格消失。当前 LayerNorm 和 GELU 更不能保证这种可加性，因此“scalars 对 L_diff 没有贡献”不成立。

附件代码统计的是 5 Å 原子对总数，没有残基对去重，也没有 BSA 或 NIS。PRODIGY 官方方案使用 5.5 Å 内的残基接触并按化学类型分类，再加入非界面表面性质，氨基酸分类也与附件不同。它的 7 标量基线可称为自定义接触/组成基线，不能视为 PRODIGY 的实现或性能复现。见 [PRODIGY 官方方法](https://wenmr.science.uu.nl/prodigy/method)。

这些描述符可从原始 PDB 离线计算并与已有 embedding 关联，无需再次运行 PPIformer。缓存只有残基级坐标，若需重原子接触/BSA，应读取原始结构。可设计标量单独、embedding 单独、二者合用三组实验，但这属于后续训练，不能预判收益。

**10. G2/G3：旧代码与当前数据状态需要区分**

预检实际分类是 `5263 audit_ready + 168 audit_ready_review + 2776 needs_review = 8207`。168 条带警告记录与 2776 条暂缓记录互斥，不应归为这 2776 条的子集。它们当前全部是 `partner_residue_without_CA`，已被保留为可审核状态；首批训练只采用无警告记录。当前 `validate_record` 已区分 issues 和 warnings，且明确暂缓非标准/多重残基身份。不能用“warnings 名字就是非致命”替代逐类可用性判断。

696 条是当前界面策略下暂缓的记录，这个分类正确。扩大界面上下文是可选设计，确实会改变图和 embedding，需要重新编码，并将扩展半径纳入缓存键和配置。需明确池化核心界面还是扩展全部节点，重新审计纳入样本和复杂度。

官方 PPIformer `utils/api.py` 对界面外突变提供的是可选推理填补：`impute=False` 为默认，打开后可填训练均值约 0.6918。它不是通过扩展图学到这些突变，也不是直接纳入绝对/差分训练的依据。若比较该官方推理策略，还需匹配单位和具体评测协议。
