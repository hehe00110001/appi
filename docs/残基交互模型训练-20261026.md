# 残基交互模型：第三轮训练

本轮将固定 mean+sum 池化后的 MLP，升级为残基交互网络和可学习注意力池化。目标是在更强的共享打分模型中，重新检验差分监督能否增加收益。正式 Slurm 数组任务为 **15821**，6 个任务、最多同时运行 2 个。启动核查时，seed42 的两组均已完成前两轮，另四个任务等待数组并发名额；后续状态以日志及 Slurm 为准。

## 模型改动

输入仍是冻结 PPIformer 的每个残基 128 维特征、坐标和结合伙伴标记。编码器不微调，使用已有缓存。

1. 线性投影到 128 维。
2. 两层残基自注意力，每层 4 个头；加入由残基距离生成的可学习偏置，以及同一/不同结合伙伴的偏置。残基能在池化前交换信息。
3. 两个结合伙伴各自做注意力池化，使用同一套池化参数。
4. 使用两侧表示的和、绝对差、乘积，以及对称的两个界面大小特征，输出一个绝对 pKd 分数。

WT 与 mutant 共用整个打分模型，差分预测仍是 `S(mutant) - S(WT)`，单位为 ΔpKd。模型不需要额外的突变位点输入。坐标只通过距离参与计算，输出对平移、旋转、残基重排及两侧交换保持不变。没有 dropout。

新模型可训练参数 **391,518**。核心变化是池化前可学习的残基交互，池化权重也可训练。

## 固定对照

沿用 `data/processed/joint_training_resplit_v1`，不删除任何记录：

| 数据 | train | val | test |
|---|---:|---:|---:|
| 绝对 pKd | 4461 | 397 | 401 |
| 配对 ΔpKd | 3063 | 268 | 270 |

两组使用相同的绝对标签、配对端点绝对标签、初始化和配对抽样序列：

- `absolute`：`L_abs + L_pair_endpoints`。
- `joint`：`L_abs + L_pair_endpoints + 0.3 * L_diff`。

配对端点损失是 WT 与 mutant 的绝对误差平方的平均。三个损失都按绝对训练标签的标准差平方归一化。λ=0.3 来自第二轮绝对验证集 RMSE 的比较，本轮固定，不根据测试集改选。网络结构升级不等于取消多项监督之间的权重。

| 数组任务 | 模式 | seed | 输出目录 |
|---|---|---:|---|
| 15821_0 | absolute | 42 | runs/affinity_residue_v1/absolute_seed42 |
| 15821_1 | joint | 42 | runs/affinity_residue_v1/joint_seed42 |
| 15821_2 | absolute | 43 | runs/affinity_residue_v1/absolute_seed43 |
| 15821_3 | joint | 43 | runs/affinity_residue_v1/joint_seed43 |
| 15821_4 | absolute | 44 | runs/affinity_residue_v1/absolute_seed44 |
| 15821_5 | joint | 44 | runs/affinity_residue_v1/joint_seed44 |

AdamW：学习率 0.001，weight decay 0.0001，梯度范数裁剪 5；有效 batch size 64，每轮 70 次参数更新；最多 200 轮，绝对验证 RMSE 连续 25 轮未改善则早停。使用验证集选最佳 epoch，最后才生成测试结果。归一化只使用绝对训练集；特征统计对唯一训练图等权，再在图内对残基等权。

每个有效 batch 通过多个小批次累积梯度；小批次最多 8 条，并限制填充后的 `B*N*N`。特别大的单个样本仍完整保留。训练配对按原对照规则有放回抽样，重复抽中的记录保留。

## 缓存与验证

`scripts/prepare_residue_cache.py` 将原有残基缓存整合为 `data/processed/residue_cache_v1.pt`（约 432 MB）：5248 张图、851126 个残基。检查了全部 3595 个唯一配对的 WT/mutant 节点顺序、坐标和结合伙伴标记一致性。没有重新编码或过滤。文件 SHA256：

```text
6ec5fbb6032af001bf9e6623a62fc29c2c42f7eb0160f7db08430953ef6af605
```

已完成以下验证：

- 7 个针对新模型的测试通过：几何/伙伴/残基顺序不变性、padding 隔离、差分恒等与反对称、交互与池化参数获得梯度、梯度累积等价、批次完整性、训练集归一化范围。
- CPU 小规模训练中，`absolute` 与 `joint λ=0` 得到逐元素完全相同的模型参数；`joint λ=0.3` 确实改变了参数，初始化和抽样状态一致。
- GPU 最大真实样本检查：2120 个残基的 WT/mutant 同批前向与反向成功，所有梯度有限；RTX 6000 Ada 显存分配峰值 6,803,329,536 bytes，约 6.34 GiB。记录在 `outputs/residue_gpu_probe.json`。
- GPU 连续训练两轮，与训练一轮后恢复到第二轮，模型、优化器、抽样器状态和 epoch 完全相同。验证作业 15818、15819 均正常结束。

这些小规模检查只验证实现和运行，不用于判断模型效果。

正式训练启动后，另核对了 seed42 两组初始化指纹、数据/缓存/代码指纹一致，未启用小样本限制，各使用全部 4461 条绝对训练记录和 3063 条配对训练记录。前两轮每轮 70 次更新，训练耗时约 38–41 秒，无数值或显存错误。配置核查摘要保存于 `outputs/residue_training_checks.json`。

提交脚本为 `scripts/train_residue_affinity.sbatch`；每个任务申请 A6000 分区 GPU 一张、CPU 4 核、内存 24 GB、时限 12 小时。若因调度时限等原因中断，使用同一配置重新提交可从 `last.pt` 恢复，启动时会核对数据、代码与配置指纹。

每轮 `epoch_XXXX.json` 分别记录训练、验证和整轮耗时及优化器更新数。结束后生成 `timing.json`、`metrics.json` 和验证/测试预测 CSV。耗时按阶段直接计时，避免用文件修改时间推测训练耗时。

本轮完成后的主线是：先比较新架构内 joint 与 absolute 的三个固定种子，判断增加差分监督是否受益；再与第二轮结果比较，判断这次整体架构升级是否有帮助。本轮同时改变交互模块和池化，不能单独归因于池化或某一层；一次架构实验也不能排除数据与科学假设问题。
