# 第二轮：固定池化，比较差分监督权重

本轮保持冻结 PPIformer、mean+sum 的 768 维池化及原有预测头，使用已固定的
`data/processed/joint_training_resplit_v1`。先回答差分监督是否带来收益，再决定是否研究池化。

**公平对照的监督定义**

两种模式均使用同一批绝对样本，以及相同的配对 WT/mutant 绝对标签：

```
L_pair_abs = mean_pairs[0.5 * ((S(mut)-pKd_mut)^2 + (S(WT)-pKd_WT)^2)] / target_scale^2
A: L = L_abs + L_pair_abs
B: L = L_abs + L_pair_abs + lambda_diff * L_diff
```

配对绝对项固定权重为 1。每个原绝对 batch 抽取等大小的配对 batch，两种模式对同一 seed
使用相同的初始模型、绝对样本顺序及配对抽样。记录中重复出现的端点按实验配对抽样保留，
不跨实验合并或平均 WT 标签；mutant 也可能已出现在原绝对表中，该共同计权在 A/B 中一致。
这是一种明确的固定训练权重，并不宣称是最优计权。

原始数据清单不变，新增训练参数 `--pair-absolute-weight 1` 控制公共端点监督。
其默认值为 0，保留旧监督目标供历史对照。两种模式仍使用同一套仅拟合于原绝对训练表的
特征/标签标准化统计，不利用验证或测试统计量。

**固定运行矩阵**

| 目录前缀 | 模式 | 差分权重 | 公共端点权重 | seed |
|---|---|---:|---:|---|
| absolute | 绝对监督 | 0 | 1 | 42/43/44 |
| joint_lambda0p05 | 联合监督 | 0.05 | 1 | 42/43/44 |
| joint_lambda0p1 | 联合监督 | 0.1 | 1 | 42/43/44 |
| joint_lambda0p3 | 联合监督 | 0.3 | 1 | 42/43/44 |

共 12 个任务，同时运行最多 2 个。每任务 CPU 2 核、内存 8 GB；不申请 GPU。
batch=64、AdamW lr=1e-3、weight_decay=1e-4、最多 200 epoch、patience=25。
每个运行继续按绝对验证 RMSE 选择最佳 epoch，测试仅在该运行选模后计算。
所有预先固定的配置均汇总，不按测试集选择 lambda 或 seed。
如果需要选定一个 lambda 用于后续阶段，只依据三 seed 的验证指标作决定，报告绝对和差分的取舍。

这轮对比同时改变了数据划分和公共端点监督，相对首轮的分数变化不能单独归因于差分损失。
研究结论应来自本轮 A/B 之间的比较。公共端点训练选项改变了训练配置和脚本哈希，
不要尝试用新版训练脚本续训首轮历史目录。

**启动**

在项目目录运行：

```bash
sbatch scripts/train_affinity_resplit.sbatch
```

新脚本固定指定新数据、各运行独立目录及公共端点监督；不要用原来的
`train_affinity.sbatch` 启动这轮，因为它指向首轮输出目录。

任务编号 0–3 对应 seed42 的四个配置，4–7 对应 seed43，8–11 对应 seed44。
输出目录为 `runs/affinity_resplit_v1/<目录前缀>_seed<seed>/`，
日志为 `logs/resplit-<作业号>_<任务号>.log`。新目录中已有 `last.pt` 时脚本自动续训，
前提是数据、代码和参数未变；重新提交整个数组不会覆盖其他运行目录。

查看运行状态：

```bash
squeue -u "$USER"
```

完成后汇总：

```bash
/home/weizg/wei/miniconda3/envs/appi-ppiformer/bin/python scripts/summarize_training.py \
  --runs runs/affinity_resplit_v1 \
  --arms absolute joint_lambda0p05 joint_lambda0p1 joint_lambda0p3
```

12 个运行齐全后输出 `runs/affinity_resplit_v1/comparison.json`，按三 seed 报告均值与标准差。
这只是 seed 间离散程度，不是复合物泛化置信区间；后续判断仍需结合按组误差。

- Slurm 脚本通过 Bash 语法检查。
